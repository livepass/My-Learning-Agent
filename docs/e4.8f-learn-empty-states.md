# E4.8f — AI 学习空态优化与归档中心收尾

基准：E4.8e `2a8de9c`。本轮只做视觉密度、归档入口文案与课程归属读取失败的修正；没有新增业务模块，没有改学习记录或课程绑定协议。

## A. AI 学习页

### A1 未选课程

欢迎语 → 课程卡片 → 输入框现在是一个连续的居中内容组：

- 列宽统一为 760px（原欢迎列 720px、输入框 980px，两列不对齐）；
- 欢迎内容与输入框共用同一个 flex 列：滚动区 `margin-top: auto` + 输入框 `margin-bottom: auto` 共同吸收剩余空间，输入框紧接卡片下方（实测间距 20px），不再固定在视口底部留下大片空白；
- 内容高于视口时两个 auto margin 归零，卡片自身滚动，标题不会被裁掉；
- 未选课程时输入框仍然禁用。

### A2 已选课程、无会话

- 标题「你想在「课程名」中学习什么？」；
- 标题下补充课程名与状态标签；
- 快捷入口收敛为三个：讲解知识点 / 开始练习 / 复习薄弱点；
- 有历史时才显示「继续之前的对话 · N」；
- 快捷入口只写草稿，不发送、不创建会话；首条消息仍走 `learning/start` 绑定课程；
- 没有新增任何进度、复习建议或掌握率。

### A3 已创建会话但没有消息

- 中央显示课程专属提示「在「课程名」中开始第一段学习」+ 一句说明 + 三个快捷问题；
- 快捷问题只填草稿；提示与输入框同组居中（实测间距 27px）；
- 已有消息时不显示该引导；
- 没有真实检查点时右侧学习状态面板默认收起，手动展开后本次访问内保持展开。

判定「真实检查点」时不看记录是否存在，而看它是否包含实际内容：`learning/start` 会在会话创建时写入一条 `step: conversation` 的占位记录，这不算学习进度。规则见 `hasRealCheckpoint()`：步骤已推进、有题目、有作答、状态非进行中或修订号大于 1 才算。

### A4 响应式

- 桌面 1440×900：欢迎组垂直居中，输入框紧随卡片；
- 手机 390×844：无横向溢出，输入框底部在底部导航之上（703 < 774），内容可滚动；
- 欢迎态与聊天态共用同一个 composer 与设计 token，只调整位置。

## B. 统一归档入口

AI 学习页原来分别有「归档课程 N 门」和「已归档会话 N」，两者都跳向同一个归档中心。现在合并为：

- 欢迎态页脚：一个「查看归档」；
- 会话侧栏：一条「查看归档（N 门课程 · N 个会话）→」。

归档业务规则未改。

## C. 课程归属读取失败

`GET /api/sessions` 原来在 `sessionCourseScopes()` 失败时退回空 Map，结果是把课程归属读取失败伪装成「所有会话都未归类」：归档中心会把课程会话错放进「未归类」，已归档课程也会凭空消失。

现在改为返回可重试的 503：

```json
{ "error": "course_scopes_unavailable", "retryable": true,
  "message": "课程归属暂时无法读取，会话列表可能不完整；请稍后重试。" }
```

- 不再返回任何 `sessions` 负载，页面显示读取失败而不是错误分组；
- 课程正常读取时行为完全不变（同一份派生逻辑）；
- 没有修改任何数据，也没有自动迁移课程归属。

## 残余风险

- 未跑全量 Vitest，未重做 E4.7/E4.8 业务验收，未在 Electron 壳内验证。
- 「真实检查点」是客户端判定（步骤/题目/作答/状态/修订号）；若将来服务端新增其他表示进度的字段，需要同步这里。
- `/api/sessions` 在课程存储不可读时整体 503：会话侧栏与归档中心都会显示读取失败，而不是降级展示部分数据——这是有意为之，避免错误分组。
- 空白对话的快捷问题固定三条，不随课程内容变化；它们只是输入提示，不声称掌握情况。
