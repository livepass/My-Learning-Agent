# E4.8a — 课程归属与对话安全收尾

基准：`fb7d7a8`。本轮只修复三处缺陷，未改 Agent、未动 L1/L2/L3/B2 结构、未改 E4.7 的归档删除规则。

## 1. 首次发送与课程切换竞态（E4.8a-1）

### 问题

`ensureConversation()` 虽然会丢弃过期结果，但 `LearningWorkspace.send()` 在 `createConversation()` 返回 `null` 后：

- 把原草稿写回**当前**（可能已切换的）课程的输入框；
- 继续执行 `sessionsStore.createSessionWith()`，即使用户提供了课程感知的创建函数——失败会退化成一条无课程归属的 Web 会话。

### 修复

- `learn-workbench-store`：
  - `ensureConversation()` 返回 `{ sessionId, courseId }`，把"这次发送属于哪门课"作为结果的一部分；
  - 创建前后都校验 `_epoch` 与 `courseId`：切换课程（`selectCourse`）、新建对话（`beginConversation`）、地址变化（`applyLocation`）、会话归属纠正（`adoptCourse`）都会 `_epoch += 1` 并清空 `request_id`；
  - 新增 `isCurrent(courseId, sessionId)`，供发送前复核；
  - 过期结果直接返回 `null`，不打开会话、不改 `error`、不删除已创建的服务端会话。
- `LearningWorkspace.send()`：
  - 发送前记录 `courseBefore` / `sessionBefore`；
  - `restoreDraft()` 只在"课程与对话意图都没变"时恢复草稿；
  - 提供了 `createConversation` 时，失败即结束本次发送，**不再回退** `createSessionWith()`；
  - 创建成功后、`chatStore.send()` 之前再次用 `isCurrent()` 校验课程与会话；
  - 无 `createConversation` 的旧调用方才保留通用创建路径。

已成功创建但因切换而未打开的会话不会被删除：服务端绑定与 B2 记录保持完整。

## 2. 服务端课程状态写入保护（E4.8a-2）

### 问题

聊天写入只拒绝 `archived`；`paused` / `completed` 的现有会话仍可通过 API 继续写入。另外 `refusesUnboundWebChat()` 在课程上下文读取失败时返回 `false`（放行），等于把故障当成"没有课程"。

### 修复

新增 `src/server/chat-write-guard.ts`，`/api/chat`、`/api/chat/stream`、`question-response` 与 `branch-before-message`（编辑历史最终也会发一轮）统一使用：

| 课程状态 | 读取历史 | 新建对话 | 继续发送 |
| --- | --- | --- | --- |
| `in_progress` | 允许 | 允许 | 允许 |
| `paused` | 允许 | 拒绝 409 `course_paused` | 拒绝 |
| `archived` | 允许 | 拒绝 409 `course_archived` | 拒绝 |
| `completed` | 允许 | 拒绝 409 `course_completed` | 拒绝 |
| 读取/验证失败 | 允许（只读） | — | 503 `course_unavailable` |

- `ResolvedCourseContext` 增加 `courseStatus`，状态判断不再只看归档标志。
- 拒绝发生在解析附件、追加消息、调用模型之前；测试用"消息数不变 + provider 调用次数不变"锁定。
- 读取失败 fail-closed（503），不再被当作"未归类"而扩大检索范围或放行模型调用。
- 非 Web 会话的未归类状态保持原样（CLI / 调度器 / IM 可继续）；`course_required` 只针对 Web。

## 3. 未归类 Web 历史只读（E4.8a-3）

- 服务端：未归类且来源为 Web 的会话（无论是否已有消息）不能发送、不能编辑重发，返回 409 `course_required`，文案说明历史仍可查看、需选择/创建课程后新建对话。
- 前端：`LearningReadOnlyReason` 增加 `"unclassified"`，学习页显示「未归类历史，仅供查看。如需继续学习，请先在左侧选择或创建课程，再新建对话。」；输入框与编辑入口都不渲染。
- 不自动绑定课程、不迁移/删除旧文件，也不改写 B2/L1；读取历史后 `session.course` 仍为 `null`。

## 7. 残余风险

- `paused` / `completed` 的聊天拒绝同时作用于非 Web 会话（课程绑定前提下），CLI 在暂停课程内继续提问会得到 409；这是状态表的直接结果，未对非 Web 另开口子。
- 未归类判定依赖 `sessions/channels.json` 或会话内容渠道；极旧、从未记录渠道的空会话会被视为内部会话（不拦截），但它不可能由当前 Web 工作台创建。
- 发送竞态依赖前端代次与 `isCurrent` 复核；服务端最终仍以会话绑定为准，不存在"消息落到错误课程"的路径，但极端并发下用户会看到一次静默放弃（草稿不恢复），需要重新发送。
