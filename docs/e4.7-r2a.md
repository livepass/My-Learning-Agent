# E4.7-R2a 定向验收

五项缺陷的最小修复与定向验证。**结论：R2a 定向验收通过**（不代表全系统完整验收）。

## 修复说明

| # | 缺陷 | 修复 |
| --- | --- | --- |
| 1 | 归档中心无法删除最后一个会话 | 归档会清空 `currentSessionId`，但运行时可仍绑定该会话；归档中心的删除请求现在始终携带 `createReplacement: true`，由服务端在 Agent 队列内判断真实绑定，必要时在同队列槽创建空白替代会话。非绑定删除会忽略该标志。确认框说明「若为当前绑定会话，会新建空白对话」。 |
| 2 | B2 读取异常未严格 503 | `server.ts` 的 `learningEvidence` 去掉 `.catch(() => undefined)`：记录缺失返回“无证据”，读取/解析失败向上抛出，由删除路由转换为 503 `course_io`；预览与 DELETE 均在写事务前中止，状态文件不变。 |
| 3 | 自动替代会话可能属于归档课程 | `selectReplacementSession` 新增 `isExcluded`；路由在队列槽内读取 `CourseStore.sessionCourseScopes()`，排除父课程已归档的会话（读取失败时排除全部候选，fail-closed）。`validateReplacement` 在切换前后各重新校验一次课程状态；无合法候选时按显式确认创建空白会话。 |
| 4 | 课程删除预览没有列出全部阻断记录 | `CourseDeletionReport` 新增 `session_details[]`（会话 ID、来源、关联任务/计划/阶段、任务状态、归档状态、B2 计数与是否有正式证据），由 store 从绑定生成、路由用 `archives.json` 与 B2 计数注解。对话框在任务明细之外列出「涉及的学习会话（N）」，每条可跳转历史；不改变删除门禁。 |
| 5 | 部分删除成功时状态不准确 | 文件删除后的 B2 / 标题清理分开执行并分别记录失败。失败时返回 500 `session_cleanup_failed`，但带 `deleted: true`、`partial: true`、`cleanup_failures`、`newActiveId`、`retryable`；前端 store 删除本地行并打开替代会话，再以 `PartialSessionDeleteError` 展示服务端说明。重试只继续清理，不重建原会话。 |

## 残余风险

- R2a-3 的路由级课程状态校验使用 `CourseStore` 替身测试；真实课程存储在队列内的耗时与并发归档尚未做浏览器级压测。
- 部分删除返回 HTTP 500 且 `deleted: true`，只按状态码判断的第三方客户端可能误读；负载中已给出 `partial` 与 `cleanup_failures`。
- `PartialSessionDeleteError` 在 UI 中仍以错误色提示（文案已说明会话已删除），未新增独立的警告样式。
- B2 fail-closed 依赖 `LearningRecordStore.get` 在损坏时抛错；后续若改为返回 `undefined`，需保留本测试。
