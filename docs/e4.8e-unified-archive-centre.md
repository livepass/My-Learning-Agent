# E4.8e — 设置页统一归档中心

基准：E4.8d `e2b7299`。本轮只改归档中心的信息结构、导航与交互，没有新增 API，没有数据迁移，也没有重写底层归档/删除事务。

## 1. 设置菜单

固定顺序：**通用与外观 → 模型连接 → 归档 → 关于**，URL 统一为 `?page=settings&tab=archive`。

- `SETTINGS_TABS` 收敛为 `general / models / archive / about`；
- 旧 id `archived-courses` / `archived-sessions` 仍在 `LEGACY_SETTINGS_TABS` 中，`resolveSettingsTab()` 把它们映射到 `archive`；
- `SettingsPage` 读到旧 id 时用 `navigate(..., { history: "replace" })` 把地址改写为 `tab=archive`，不新增历史条目；
- `pageUrl()` 也把任何旧 tab 归一化为 `archive`，新链接不会再把旧参数写回；
- `LearnPage`（归档课程/会话入口）、`TodayPage`、`CoursePlanPanel`、`LearningWorkspace`、`DeletionDialog` 的文案与跳转都指向「归档」。

## 2. 归档中心分组

新组件 `web/src/react/settings/ArchiveSettings.tsx`，分组由 `buildGroups(courses, sessions)` 纯函数计算，**只按真实 `course_id` 关联**，同名课程也分成两组。

| 类型 | 条件 | 课程行 | 会话行 |
| --- | --- | --- | --- |
| A | 课程 `archived` | 课程名 +「已归档」+ 会话数；课程详情 / 学习记录 / 恢复课程 / 删除课程；无会话的归档课程也显示 | 该课程**全部**会话，标注「手动归档 · 课程已归档」或「随课程归档」+「只读」；恢复会话禁用（提示「请先恢复所属课程」） |
| B | 课程正常，有手动归档会话 | 只显示课程名与「N 个会话已手动归档」，无已归档标签、无恢复/删除课程 | 仅 `session.archived === true` 的会话，可查看 / 恢复 / 删除 |
| C | 两者都归档 | 同 A（显示已归档） | 全部会话，逐行区分手动归档与仅随课程归档 |
| D | 无课程绑定的旧版手动归档会话 | 「未归类归档会话」分组，不伪造课程、不自动绑定 | 查看历史 / 恢复 / 删除 |

普通未归档会话不会出现在任何分组；没有任何归档内容的普通课程不显示。排序：归档课程 → 正常课程（按标题）→ 未归类。

## 3. 操作后即时更新

- `coursesStore.restoreCourse()` 现在在成功后额外 `sessionsStore.refresh()`：课程恢复会改变服务端派生的 `course.archived` / `daily_visible`，不刷新会话列表分组就会停在旧状态。
- `ArchiveSettings` 的恢复课程 / 恢复会话 / 删除会话在成功后都重新读取两侧数据；`DeletionDialog` 的 `onDeleted` 触发 `refreshAll()`。
- 所有操作都是「先请求、后更新」：失败时记录不动，错误显示在页面上。
- 恢复课程后：课程状态为 `paused`；仅随课程归档的会话退出归档中心；手动归档会话保留并归入正常课程分组，可再单独恢复。子会话的手动归档标记从不被批量清除。
- 删除归档课程沿用 E4.8d 的 `DeletionDialog` 风险确认与安全级联删除，成功后课程与子会话同时从列表消失。

## 4. 交互与视觉

- 分组卡片可展开/收起；展开状态存在组件本地 `collapsed` 映射里，普通数据刷新不会重置。
- 会话是缩进的子列表，课程标题 15px / 会话标题 14px，层级清楚。
- 手机（≤900px）：课程级操作折叠为「…」菜单；会话按钮换到标题下方一行；分组标题独占一行，标签不再被挤断。
- 加载失败显示「归档内容读取失败」+ 重试，**不会**显示空状态；空状态统一为「暂无归档内容」。
- `sessionsStore` 新增 `loadError`（失败时 `sessions` 仍清空，但页面能区分「空」与「读不到」）。

## 7. 实机检查

临时数据目录 + 当前构建（3101 端口）：

- 桌面 1440×1000：归档课程（1 手动 + 1 随课程）与正常课程（1 手动）两组；课程级按钮四个、会话级三个。
- 恢复课程后：该课程不再显示「已归档」，随课程归档的会话消失，手动归档会话保留（2 组 → 2 组，会话数 3 → 2）。
- 再恢复最后一个手动归档会话：该课程分组整体消失，只剩正常课程组。
- 旧链接 `?tab=archived-courses` 打开后地址变为 `tab=archive`，激活标签为「归档」，`history.length` 不变。
- 手机 390×844：无横向溢出；课程操作在「…」菜单中（课程详情 / 学习记录 / 恢复课程 / 删除课程）；会话按钮换行。

## 8. 残余风险

- 未跑全量 Vitest，未重做 E4.7/E4.8 业务验收，未在 Electron 壳内验证。
- 归档中心依赖 `GET /api/sessions` 的 `daily_visible` / `course.archived` 派生字段；旧服务端若缺字段，分组会退化（归档课程仍能按 `status` 识别）。
- 课程级「删除课程」仍只对已归档课程提供；正常课程若想删除，需要先归档，这与 E4.8d 规则一致。
- 手机端课程操作在菜单里，比桌面多一次点击。
