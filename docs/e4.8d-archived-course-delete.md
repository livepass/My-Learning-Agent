# E4.8d — 归档课程永久删除规则

基准：E4.8c `c4512c7`。目标：只要课程已归档，用户在确认风险后即可永久删除，不再因为存在学习会话、任务、B2 或 L1 记录而被业务阻断；同时不允许留下孤儿数据或误报删除成功。

未改动：课程绑定规则、聊天运行时、学习计划与归档规则（E4.7 / E4.8 的业务验收未重跑）。

## 1. 新的删除门禁

| 条件 | 结果 |
| --- | --- |
| 课程未归档 | 拒绝（`course_not_archived`），提示先归档 |
| 已归档，有会话 / 任务 / B2 / L1 | **允许**；这些数据只作为风险计数展示 |
| 已归档，仍有未结束的 `learning/start` | 拒绝（`pending_learning_start`，瞬时状态，可重试） |
| L1 或 B2 读取失败 / 数据损坏 | 503 `course_io`，不删除任何东西 |
| 会话清理失败 | 500/409 明确失败，课程保留，可重试 |

`CourseDeletionReport` 新增 `archived`、`b2_evidence_sessions`、`b2_evidence_attempts`；`blockers` 里不再出现 `course_sessions` / `started_tasks` / `learning_evidence` / `mastery_states`。

## 2. 课程级安全级联删除

`CourseStore.deleteCourse(courseId, { cleanupSessions, beforePurge })` 分两阶段：

1. **先清理会话（由 session 模块这个唯一所有者执行）**：
   - 逐个会话走既有的 `deleteSessionFileInQueue`，在 Agent 队列内决定运行时是否仍绑在该会话上；
   - 运行时仍绑定时，先切到课程外的已有会话；没有可用会话时**新建一个空白会话**接手（SDK 没有「无会话」状态，否则下次写入会重建文件）；
   - 随后删除该会话的 B2 记录（`learningRecordStore.remove`）、会话元数据（`sessionMetaStore.remove`）与全部 sidecar（渠道元数据、归档标记、题目元数据、附件、命令、trace、btw、workspace activity、课程绑定）；
   - 每一步独立 try/catch，任何一步失败都会留下 `session-cleanup` 标记并让课程保留，绝不把半清理的会话算作成功。
2. **一次 `state.json` 写入**删除课程行、计划、阶段、任务、目标与教材**关联**、课程设置、启动记录；
   - 写入事务会重新核对绑定集合：如果清理后仍有绑定（例如清理期间新增），整体回滚并返回 409，而不是把绑定删掉假装会话已清理。
3. `beforePurge` 清理课程专属 L1（`forgetCourseProfileData`：删除带该 `course_id` 的知识点状态，以及仅属于这些概念、且非人工维护的误解记录）与 L3（`L3Memory.forgetSession`：按会话 id 删除索引块）。

**保留项**：L2 教材文件本身（只删关联）、学习目标、其他课程的会话与 L1/L3 数据、未分类/旧版状态、共享资料。

## 3. 删除确认界面

`DeletionDialog` 对已归档课程展示：课程名、会话数、计划/阶段/任务数、已开始任务数、B2 正式证据（会话数 + 记录数）、L1 掌握状态数、不可恢复内容、仍会保留的共享数据，并明确「删除后无法恢复」。未归档课程改为「该课程现在不能永久删除」+ 先归档指引，不再出现「已有真实学习记录，只能归档」。

`ArchivedCoursesSettings` 的删除入口保持不变，注释更新为 E4.8d 规则。

五个定向场景（`server.e48d-course-delete.test.ts`，真实服务端 + 真实文件 + 真实 B2/L1）：

1. 已归档空课程删除：200，`complete: true`，课程 404。
2. 已归档多会话/多任务课程：预览 `sessions: 2`，删除后会话文件、B2 记录、`/api/sessions` 行全部消失。
3. 有正式 B2 证据与 L1 掌握状态：预览给出 `b2_evidence_sessions: 1`、`b2_evidence_attempts: 1`、`mastery_state_count: 1` 且 `deletable: true`；删除后课程证据消失，未分类 L1 状态保留。
4. 删除课程 A 不影响课程 B：B 的课程、会话文件、B2 记录、L1 状态都在；共享教材仍在 manifest 且仍由 B 关联；L1 只剩 B 与共享状态。
5. B2 记录损坏：预览与删除都返回 503 `course_io`，课程、会话文件、B2 记录原样保留。

## 6. 浏览器实测

在临时数据目录启动构建产物（3100 端口）后，于归档中心对「有历史的课程」（1 计划 / 1 任务 / 1 会话）执行删除：

- 对话框列出课程名、会话 1 个（聊天记录与学习记录一并删除）、已开始任务 1 个、B2 0 个会话 0 条记录、L1 0 个，并说明保留项与不可恢复；
- 二次确认后课程从归档列表消失，`GET /api/courses` 为空，`/api/sessions` 只剩新建的空白接手会话，`data/learning/` 为空。

## 7. 未执行与残余风险

- 未跑全量 `npx vitest run`（按定向要求），未重跑 E4.7/E4.8 业务验收。
- 未在 Electron 壳内验证。
- 运行时被绑定时，若课程外没有可用会话，会新建一个空白会话作为接手者；这是 SDK 无「无会话」状态下的必要行为，会产生一个空会话文件。
- L1 的事件账本（`events.jsonl`）保持只追加：删除课程不会改写历史事件，只移除课程专属状态；若将来按账本重建画像，这些事件仍会被重放，但课程绑定已不存在，因此不会重建出该课程的归属状态。
- 会话清理失败时课程保留并写入 cleanup 标记，需要用户重试；没有后台自动清理任务。
