# E4.7-R2a 收尾修复

只修复 R2a-5 的两个异常路径。**结论：收尾修复完成，E4.7 系列可关闭。**

## 修复 1：B 初始化不再被 A 的清理失败跳过

- 空白替代会话 B 的 `channel/origin` 与工作区绑定提前到 A 的任何清理之前执行；B2、标题、附属数据的失败不会再跳过 B 的初始化。
- B 初始化失败时记入 `cleanup_failures: ["replacement_init"]`，接口仍返回 `deleted: true`、`partial: true`，绝不谎报完整未删除。
- 重试根据持久标记中的 `new_active_id` 幂等补齐 B 的初始化；不重新创建 B。

## 修复 2：附属数据清理可逐项重试、可跨重启

- 渠道、归档标志、题目元数据、附件、命令、追踪、btw、工作区活动、课程绑定各自独立 `try/catch`；一项失败不跳过其余步骤。
- 任一未完成项写入 `data/sessions/pending-cleanup.json`（每会话一条，含失败步骤与可选 `new_active_id`），接口返回 500 `session_cleanup_failed` + `deleted: true` + `partial` + `cleanup_failures`。
- 重试读取标记，跳过运行时交接（避免再次创建 B），只重跑清理；全部成功后删除该条目。
- 标记采用模块内串行读改写，避免两个并发删除互相覆盖。
- 全部成功后响应 `cleanup: "complete"`。

## 残余风险

- 崩溃窗口：聊天文件删除成功、但清理标记尚未写入时进程崩溃，仍可能留下无标记的附属数据；窗口很小，未引入事务日志。
- 标记模块的串行锁是进程内锁；多进程同时删除同一批会话不在当前部署模型内。
- 若 B 在两次重试之间被外部删除，`replacement_init` 会持续失败并保留标记，需要人工清理该标记。
