## 1. 原始改造目标

来自 `analysis.md`（P1 现状分析）与 `prototype-a.html`（方案 A「概览优先」，用户确认）：

1. **一套状态语义。** 同一知识点在全部课程、指定课程、课程概览三处必须显示同一个状态；
   状态只来自服务端 `state_label`，不得由掌握度阈值或复习日期推断。
2. **六个概念不互相替代。** 状态、掌握度、证据数量、任务进度、来源、正式复习资格各自独立，
   界面不得用其中一个暗示另一个。
3. **数据可信度可见。** 服务端已返回 `origin` / `provenance_unknown`，界面必须显示，且不得转述为质量评分。
4. **编辑安全。** 编辑期间的被动刷新、筛选切换、课程切换、保存失败都不得丢草稿或改写未编辑字段。
5. **移动端可用。** 320/390px 下无裁剪、无横向溢出，长名称可换行。
6. **不虚构能力。** 没有证据明细接口就不做明细；没有可信度算法就不显示评分。

## 3. 五个维度的最终结论

### 3.1 状态语义统一 —— 已统一

- 三个视图全部使用 `KnowledgeStateBadge` → `knowledge-state.ts` 的单一映射。
- P2-7 修掉了最后一处例外：课程概览此前把 `unknown` / 缺失 / 非法值画成 `success`，并把非法值原样渲染。
- 证据：`CourseDetailPage.test.tsx` T01-1…T01-4（修复前 4 项失败）、`LearnerProfilePanel.knowledge-state.test.tsx` 23 项、
  浏览器 B04（8 概念 × 3 视图逐项相等）、B05（缺失/非法三视图降级）。

### 3.2 课程范围隔离 —— 已隔离

- 页面不合并、不缓存、不补齐：三个范围各自读服务端返回的记录。
- 相同 `concept_id` 在三处有不同 state/mastery/origin/证据数/诊断，切换后互不残留（C01–C12、B06）。
- 迟到响应由 store 的 ticket + `courseScoped` 丢弃（C11、B18）。
- 课程视图只读（C12、B02、B09）。

### 3.3 学习档案编辑安全 —— 已覆盖

- 摘要、知识点、目标、筛选、课程切换、保存失败、来源标签、异常端点均有既有测试，本轮全部复跑通过。
- R2 的 S01–S18（目标编辑快照）全部保留并通过。
- 本轮未新增编辑安全测试，也未修改任何编辑实现。

### 3.4 数据可信度语义 —— 已明确

- 来源只说明"谁产生"，不表示质量：`origin` 三态 + `provenance_unknown` 独立显示。
- 证据数量是标识数组长度，不去重、不补齐；不可读时显示「证据标识数量不可用」。
- 待复习徽章 ≠ 正式复习资格：`reviewable()` 只看证据、来源、provenance 与日期（V01–V08）。
- 本轮未新增可信度评分、未新增证据明细接口。

### 3.5 响应式布局 —— 已验收，留一处已知缺陷

- 320/390px 三视图、长名称、英文、深色均无裁剪与横向溢出（B11–B16）。
- **K-01**：320px 折叠态目标卡片的内容列仅 18px，标题逐字换行。既有问题，已登记、附实测与截图，本轮不修。
