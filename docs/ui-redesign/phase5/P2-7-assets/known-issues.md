## K-01 · 320px 折叠态学习目标卡片内容列过窄

| 项 | 内容 |
| --- | --- |
| 缺陷编号 | K-01 |
| 复现条件 | 视口 320px，学习档案页（全部课程），学习目标区存在至少一个折叠态目标卡片 |
| 实测数据 | 卡片宽 232px；右侧「状态 + 编辑 + 删除」按钮组 149px；左侧内容列 **18px**，标题逐字换行 |
| 页面横向溢出 | `document.scrollWidth == clientWidth == 320`，无横向溢出 |
| 缺陷来源 | **P2-6-R2 之前已存在**。在 `main@59d6118` 上把 `LearnerProfilePanel.tsx` 回退到该版本后，同一探针测得完全相同的 232 / 149 / 18；P2-6-R2 的 diff 也未触碰折叠态 JSX 与任何样式 |
| 影响 | 折叠态目标标题阅读困难；不影响编辑态（展开后为单列 grid，320px 可正常操作），不影响任何读写语义 |
| 本轮处理 | **只登记，不修**。P2-7 冻结范围禁止修改 P2-5 响应式布局机制，本轮唯一授权改动是课程概览的状态徽章复用 |
| 证据 | `P2-7-assets/known-issue-320-goal-card.png`；`browser-metrics.json` 的 `knownIssue` 字段 |
| 后续处理 | 独立响应式 UI 修复任务：让折叠态卡片在窄视口下把按钮组换行或收纳，不与本轮合并 |

## K-02 · 客户端 `isActionableReviewDue` 与服务端 `reviewable()` 是两份实现

| 项 | 内容 |
| --- | --- |
| 复现条件 | 任一侧单独修改正式复习规则（例如新增来源要求、调整日期边界）而未同步另一侧 |
| 现状 | `web/src/utils/review-eligibility.ts` 镜像了 `src/courses/daily-plan.ts:140` 的四条判定：证据 ≥ 1、`origin === "derived"`、`provenance_unknown !== true`、日期可解析且不晚于当前 |
| 影响 | 若两边漂移，今日学习页可能展示服务端不会生成的复习条目（或漏掉）。展示层不会写入资格，因此影响限于"多显示/少显示入口" |
| 本轮处理 | **不修**。T04 只验证现有规则，冻结范围禁止修改正式复习资格；本轮新增 8 项边界测试（V01–V08）固定当前一致行为，任一侧改动都会让这些用例失败 |
| 后续处理 | 若要彻底消除重复，需要把规则下沉到 `shared/` 并由服务端与前端共用；属于独立重构，不在 E4.9i 范围 |
