## 6. 抽屉、Sheet 与子菜单焦点行为

浏览器真实按键实测（1279 / 1024 / 901 / 900 / 390 / 320 六档一致）：

| 检查 | 结果 |
| --- | --- |
| 抽屉关闭时内部不可 Tab 进入 | 是（`inert`） |
| 打开后焦点进入抽屉 | 是 |
| Tab / Shift+Tab 不逃逸 | 是（12 次 Tab + 6 次 Shift+Tab 均未离开） |

| Escape / 关闭按钮 / 遮罩 | 均可关闭 |
| 焦点回收 | 回到「打开课程列表」按钮 |
| 会话更多菜单 | 键盘可开，显示在抽屉之上 |
| 菜单 Escape | 只关菜单，抽屉存活 |
| 关闭后 Tab 不进入隐藏抽屉 | 是 |
| 视口切换无残留模态 | 是（P2-4-R1 已专项验证） |
| Sheet 桌面非模态 / 手机模态 | 是（`role` 与 `aria-modal` 随视口切换） |

**滚动锁实现（P2-5-R1 更正）**：两种弹层的实现**并不相同**——

- `modal-layer.ts`（历史抽屉）：模块级引用计数，第一个进入时记录原始值并锁定，最后一个离开时恢复；
- `Sheet.tsx`（学习上下文）：每次打开保存 `body.style.overflow` 的当前值，关闭时写回。

原文「两者均采用引用计数」不准确，已更正。两种实现的交互结果经 P2-5-R1 实测验证：4 档视口 × 5 轮快速开关共 20 轮，每轮结束 `body.style.overflow` 均为空、`inert` 回到仅关闭抽屉的状态、无控制台错误。原因是两种弹层在 UI 上互斥（打开一个必然关闭另一个），不存在同时持有锁的时刻。详见 `P2-5-R1-acceptance.md`。

## 8. 发现的问题与修复

### P1：重命名会话后，该会话在 UI 中被误判为未归类

**复现**：打开任一已绑定课程的会话 → 抽屉内「更多 → 重命名」→ 保存。该会话立刻从课程列表消失，并出现在「未归类历史」下。

**证据**：`PATCH /api/sessions/:id` 的响应体不含 `course` / `daily_visible` 字段（服务端返回的是解析后的会话摘要，课程归属是派生字段，由列表接口附加）。客户端 `renameSession` / `generateSessionName` 用这个响应**整体替换**了列表中的会话对象，于是绑定信息被抹掉。服务端绑定本身完好——刷新页面即恢复，所以它是纯客户端的状态污染。

**影响**：用户重命名后，课程栏、历史栏、权限判断都会按「未归类」处理，属于权限相关的错误展示（P1，非 P0：不会把写权限误放行，只会过度收紧）。

**修复**（[sessions-store.ts](apps/learning-agent/web/src/stores/sessions-store.ts)）：新增 `applySessionSummary`，改为**合并**而非替换——响应未提供的字段（`course`、`daily_visible`、`archived`）保留原值，响应拥有的字段（`name`、`preview`、`hasTopic` 等）仍以服务端为准。`generateSessionName` 走同一条路径（它有完全相同的缺陷）。

**回归测试**：`sessions-store.test.ts` 新增 2 项——重命名与自动生成标题后，`course` / `daily_visible` / `archived` 均保留。

**复验**：修复后重跑同一流程，抽屉内 `rows: 1`，会话仍在课程列表。

## 11. 未解决风险与覆盖范围

### 11.1 验收覆盖范围（P2-5-R1 明确区分）

**真实浏览器已执行的流程**

- A 从零开始：欢迎态 → 创建课程 → 快捷草稿 → 首次发送 → 绑定 → 流式回复

- C 会话管理：抽屉内重命名、归档；归档后回到欢迎态并在那里新建会话
- D 学习状态：打开 Sheet → 显式初始化 → 暂停 → 继续 → 关闭
- E 权限：归档课程的只读态
- 八档视口的状态矩阵、键盘 Tab/Shift+Tab/Escape、深浅主题、中英文

**仅由自动化测试覆盖（未在浏览器中走完）**

- **删除会话**：浏览器端到端未执行——删除会永久移除测试会话，且需要 `window.confirm` 与替换会话协商。由 `LearnPage.test.tsx` 的 5 项用例覆盖（含 `no_replacement_session` / `replacement_create_failed` / `replacement_unavailable` 三种 409 分支）。

- **课程暂停 / 完成的浏览器流程**：只在自动化中覆盖；浏览器里执行的是「归档课程」这一种权限状态。
