现状：对话被两侧面板夹住

01 / CURRENT

现有页面并不是功能不足，而是布局把「对话」放在了第三位：左栏 260px、右栏 240px，1024px 下聊天区只剩 452px。下面是真实构建产物在受控数据下的测量，不是设计稿推测。

  • P11024px 聊天区只剩 452px。中文正文每行约 20 字，代码块和表格频繁换行；两侧面板合计占掉内容宽度的一半。
  • P2右栏信息密度低，却长期占 240px。通常只有阶段、修订、题目和一个暂停按钮；没有检查点时折叠成 40px，展开后仍固定挤压聊天。
  • P3历史与换课入口不一致。欢迎页是「继续之前的对话」文字链接；会话态是 260px 左栏；进入会话后换课要先退回欢迎页。
  • P4垂直 chrome 偏高。顶栏 + 会话头 + 上下文条叠在消息之前；1024px 下上下文条换成两行，进一步压缩首屏。
  • P5课程上下文与学习状态分离。课程/任务/阶段在聊天上方，检查点在右栏；任务不可点击，用户无法从这里进入计划。
  • P6移动端学习状态实际不可见。状态面板排在聊天卡下方，要先滚过整段对话才能看到；没有抽屉或底部 sheet 入口。

三种布局方向

02 / DIRECTIONS

三种方向都保留现有业务语义：选课不创建会话、快捷操作只填输入框、首次发送才创建会话。差别在于「历史放在哪里」与「学习状态是否常驻」。

上下文按需覆盖

A · 专注书桌

推荐成本 中

≥1280px 保留 264px 历史栏，聊天占满剩余宽度，阅读列最大 880px；1024–1279 历史栏变抽屉，聊天占满工作区。学习状态改为右侧 360px sheet，默认关闭，从课程栏或会话头打开，覆盖而不挤压聊天。

优点

  • 1024px 聊天区 452 → 960，正文最大 760
  • 历史在宽屏常驻，窄屏一键抽屉
  • 课程切换、任务、阶段集中在一条课程栏
  • 上下文按需出现，不长期占位

代价

  • 需要新的课程栏、历史栏与上下文 sheet
  • 默认关闭状态下，状态需要一次点击
  • 移动端要新增底部 sheet 与抽屉
适合：以长文讲解、代码和连续追问为主的学习场景。改动：LearnPage 重组 + 4 个展示组件
右栏常驻

B · 三栏工作台

成本 低–中

保留现有 260px 历史栏与右侧学习状态栏，只把右栏压到 280px 并在 1100px 以下折叠。课程栏替换聊天头与上下文条，减少垂直 chrome；聊天仍然会在 1024px 被右栏挤压。

优点

  • 结构最接近现状，迁移风险最低
  • 历史与状态同时可见
  • 可直接复用当前 LearnPage 的三栏 CSS

代价

  • 1024px 聊天仍只有约 600px
  • 右栏信息密度低的问题没有解决
  • 视觉上仍偏「管理控制台」
适合：希望最小改动、先解决入口问题的迭代。改动：LearnPage + CSS
课程驾驶舱

C · 课程驾驶舱

成本 中–高

顶部用今日学习同款的课程渐变 hero，横向列出最近会话；聊天占满剩余宽度，学习状态用右侧 sheet。课程身份最强，但 hero + 会话条会占掉首屏约 150px 垂直空间。

优点

  • 课程身份与最近会话最醒目
  • 聊天宽度最大
  • 与今日学习的视觉语言最一致

代价

  • 垂直 chrome 更高，首屏消息更少
  • 横向会话条只能放 3–4 个
  • 需要新的 hero 与横向滚动组件
适合：课程数量少、强调课程品牌感的产品。改动：LearnPage 重写 + hero/会话条

推荐 A · 专注书桌

03 / RECOMMENDATION

理由很直接：在不牺牲历史与上下文的前提下，把 1024px 的聊天区从 452px 提升到 960px，正文最大 760px。历史在宽屏仍然常驻，学习状态按需出现，课程切换始终在课程栏里。

布局规则

≥ 1280px
264px 历史栏固定；聊天列最大 880px（正文最大 760px）；上下文 sheet 360px 覆盖右侧。
1024–1279px
历史栏变为 320px 左抽屉；聊天占满工作区，阅读列仍最大 880px；上下文 sheet 覆盖。
≤ 900px
全局图标栏变底部导航；课程栏 56px；历史抽屉 + 学习上下文底部 sheet；composer 在导航之上。
课程栏
课程切换、当前任务、阶段、学习状态入口、新对话。手机隐藏任务 chip，任务在上下文 sheet 中展开。
视觉
沿用今日学习 B 的 token：12px 卡片圆角、1px 边界、克制的 soft shadow；不用大面积渐变，不让装饰抢对话。

为什么是 A

  • 阅读优先。1024px 聊天区从 452px 提升到 960px，正文最大 760px；1440px 仍保持同一行长，而不是把多余宽度铺成空白。
  • 历史不消失。宽屏常驻 264px；1024–1279 一键抽屉；手机 86% 抽屉。会话多时靠滚动与分组收敛，不截断。
  • 上下文不常驻。学习状态是「需要时看一眼」的信息，不是每秒钟都要占 240px 的导航。
  • 课程始终可见。课程切换、当前任务、阶段在一条栏里；不需要先退回欢迎页再换课。
  • 改动可控。LearningWorkspace、所有 Store 与 API 不动；只重组 LearnPage 的展示层。

状态与交互

05 / STATES

原型覆盖 10 个可切换状态；下表另列出「进行中 / 继续历史」两种由真实数据自然产生的形态。所有状态都只读现有真实字段；没有掌握度、没有伪造进度、没有自动发送。

必须保留的语义

  • 快捷操作只填输入框：不调用 send，不创建会话。
  • 首次发送才创建会话：`ensureConversation` → `learning/start` → 绑定成功后才发送。
  • 课程切换清空草稿：避免 A 课的问题发到 B 课。
  • 会话绑定来自服务端：不按标题猜测课程。
  • 任务完成 ≠ 知识掌握：上下文只描述检查点，不推断掌握度。

交互细节

  • 课程切换：更新课程栏与历史；关闭当前会话；草稿清空；不创建会话。
  • 会话切换：加载历史；更新 URL；回填服务端课程绑定。
  • 新对话：回到当前课程的起点；第一条消息才创建会话。
  • 上下文：`aria-expanded`；桌面非模态、点击外部关闭；手机遮罩、Escape 关闭。
  • 只读 / 阻塞：composer 被说明替代；恢复/归档是唯一动作。
  • 焦点：所有触发器 2px accent 轮廓；sheet 关闭时 `inert`。
