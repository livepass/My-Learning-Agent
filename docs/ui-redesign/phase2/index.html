01相较第一阶段的修正

先把「不能凭空造」的部分修掉

第一阶段是方向稿，允许用演示数据把气质做出来。进入交互阶段后，原型里的每个元素都必须能在现有代码与接口里找到依据。

FIX 01

去掉顶栏搜索

应用没有全局搜索接口。B 的顶栏只保留「创建课程」与「系统设置」，不再放一个点了没反应的搜索框。

FIX 02

封面不再写虚构课号

「EN 210 · ACADEMIC WRITING」这类课号在数据里不存在。改为真实的「第 3 阶段 · 结果与讨论」，封面只承担识别，不承担编造。

FIX 03

主课标题降到 24px

27px 是第一阶段的一次性字号。24px 与现有页面标题同一档；层级仍由渐变、字重和留白建立。

FIX 04

建议默认 1 条，可展开

接口最多返回 3 条。默认展示最相关的一条，条内「另有 N 条」展开其余建议，不新增页面、不丢数据。

FIX 05

复习保留逐条开始

不做「批量复习」这种新流程。复习卡最多列 2 条，其余通过「查看知识状态」进入学习档案。

FIX 06

管理动作保持次级

归档 / 删除仍在课程行的「更多」菜单里，菜单只在悬停或键盘聚焦时提高可见度；课程详情页保留同一组动作，不在首屏露出破坏性操作。

实施记录（2026-11-20）：今日页已按本规格落地到 apps/learning-agent/web。唯一偏差是保留现有 64px 图标栏，没有改成 248px 文字侧栏——改导航会同时影响 AI 学习、练习、档案与设置四个页面的可用宽度；248px 侧栏作为可选的后续导航改造。
02页面结构

一屏之内，只有一个主操作

左侧导航与顶栏固定，只有内容区滚动。主课横幅承担「现在做什么」，任务区承担「还剩什么」，下半区承担「我在学什么」。

01 02 03 04 05
  1. 01顶栏 · 64px。页面标题 + 日期；右侧「创建课程」「设置」。不放搜索、不放面包屑；它不随内容滚动。移动端 56px，日期隐藏。
  2. 02主课横幅。只放一个任务或一个课程状态（暂停 / 无计划 / 完成）。主课取非归档课程中 updated_at 最新的一门，其状态决定横幅；当日任务全部完成时优先显示完成态。一个主按钮 + 一个次级入口；进度条只表达任务进度，不宣称掌握度。
  3. 03今日任务 · 首屏 3 张卡。主课之外的 2 个任务 + 1 张复习卡；其余任务折叠为「另有 N 项」，展开后同区列出，不把任务藏进课程详情。卡片、复习、课程行都只读服务端字段，不在前端推导掌握度。任务区按 280px 最小宽度自适应，窄容器自动降为 2 列 / 1 列。
  4. 04AI 建议条。默认 1 条；「另有 N 条」在条内展开，不跳页。所有建议都来自 /api/learner/recommendations，不本地生成。
  5. 05下半区。「我的课程」+ 右栏「最近学习」「学习目标」。课程行显示进行中 / 已暂停 / 已完成 / 无启用计划，完成课程只保留记录入口；右栏不承载新的写操作。
顺序不变：桌面、平板、手机保持同一阅读顺序（主课 → 任务 → 建议 → 课程 / 会话 / 目标），只改变列数与密度，不把主操作藏进菜单。
03交互模型

先拿到会话，再离开页面

今日页最重要的约束只有一句：开始学习不是一次跳转，而是一次写入。 只有 POST /learning/start 返回了绑定会话，才允许进入 AI 学习；失败时用户必须留在原页面、保留滚动位置。

主流程 失败后的重试 所有写入由 coursesStore 的 pendingAction 串行化
暂停 → 继续课程 → 默认 无计划 → 制定计划 → 课程详情 完成 → 查看记录 / AI 学习 三条支线都不创建会话
动作触发调用成功后失败 / 约束

POST /api/courses/:id/learning/start		 navigate("learn", { session }) → openSession → loadSessionContext → recordStartWarnings 失败留在本页。显示服务端原因；焦点移到提示；按钮恢复；不创建空会话。
继续课程 暂停横幅 coursesStore.resumeCourse(courseId)
POST /api/courses/:id/resume		 刷新 courses / daily / detail，回到默认态 只改状态，不创建会话；失败保留暂停态并提示。
制定计划 无计划横幅 navigate("course", { id, view: "plan" }) 进入课程计划页 只读导航；不在今日页生成计划。
查看课程 横幅次级按钮、任务卡「课程」、课程行 navigate("course", { id, view: "plan" }) 课程详情 · 计划页 只读导航；课程归档/删除仍在详情页。
开始复习 复习项 navigate("practice", { session, review: { conceptId } }) 练习页携带复习意图 不创建会话、不调用模型。练习页会重新读取档案并拒绝过期概念。
前往 AI 学习 建议条 / 完成态 navigate("learn")；review/practice 类建议走练习页 对应页面 不自动生成问题，不自动调用模型。
打开会话 最近学习 navigate("learn", { session: id }) → openSession 打开已有会话 与页面写入同一条 history，Back 回到今日页。
创建课程 顶栏 / 空态 CreateCourseDialog → coursesStore.createCourse 进入新课程的计划页 标题必填、≤120；说明可选、≤4000；失败保留输入。
查看归档课程 空态 / 错误态 navigate("settings", { settingsTab: "archive" }) 系统设置 → 归档 只读导航；不在今日页恢复课程。
重试 错误态 / 开始失败 loadCourses / loadDaily 或重新 startLearning 恢复原状态 重试期间按钮禁用；不叠加第二次请求。
四条硬约束：① 同一时刻只允许一个写操作（pendingAction），其余开始按钮全部禁用； ② 成功后只写一条 history，页面与会话一起进入，Back 不经过空白学习页； ③ 失败时滚动位置不变，焦点移到 role="alert" 的提示上； ④ 复习 / 建议只做导航，不隐式创建会话或调用模型。

06键盘、焦点与动效

状态变化必须能被看见，也必须能被读到

项目规则
焦点顺序顶栏 → 主课按钮 → 任务卡按钮（按视觉顺序）→ 复习项 → 建议 → 课程行 → 会话 → 目标。卡片本身不入 Tab 序，只有内部按钮可聚焦。
焦点环2px 强调色，offset 2px；鼠标点击后不显示键盘焦点环。菜单、对话框、卡片按钮共用同一规则。
开始失败提示使用 role="alert" 且 tabindex="-1"；失败后焦点移到提示，读屏立即播报原因。
创建对话框打开时聚焦标题输入；Tab 在对话框内循环；Escape 关闭（提交中除外）；关闭后焦点回到触发按钮。
状态不只靠颜色暂停、逾期、完成都同时有文字或图标；进度条有数字与文本，不只靠长度。
动效卡片 hover 抬升 2px、120–180ms；骨架高光 1.5s；prefers-reduced-motion 下取消抬升与骨架高光，只保留颜色变化。
触控移动端按钮与行高 ≥44px；复习项整行可点；底部导航四个入口等宽。

验收清单

  • 开始学习：成功后才跳转；失败留在本页、滚动不动、焦点落在提示上。
  • 并发：开始中所有「开始 / 继续」禁用；不产生第二个会话或第二次写入。
  • 暂停：继续课程只恢复状态，不创建会话；任务区不出现该课程。
  • 无计划：制定计划进入课程 plan 页，不在今日页生成计划。
  • 复习：逐条进入练习页，携带 conceptId；不创建会话、不调用模型。
  • 建议：默认 1 条，展开后能看到全部 ≤3 条；收起后焦点回到展开按钮。
  • 空 / 错：课程与每日计划可以分别失败；整页错误只用于课程列表失败。
  • 断点：1440 / 1024 / 900 / 390 / 320 均无横向滚动；主操作始终可见。
  • 主题：light / dark 下封面、横幅、骨架、提示都有足够对比度。
  • 键盘：Tab 顺序符合视觉；对话框焦点陷阱与 Escape 正常；减少动效时不抬升、不做骨架高光。
建议分两步提交：① token + CourseCover + 静态布局 + 组件测试；② 全部状态、失败路径、响应式与 a11y 对齐。第一步就能看到完整视觉，第二步再补行为，评审和回滚都更可控。
