## 3. C1–C4 与复习流程完整性

| 协议 | 原型是否保留 | 证据 |
| --- | --- | --- |
| **C1** 生成题目（概念/题型/来源） | 是 | 出题表单 4 个字段完整 |
| **C2** 提交答案、只读、独立评分 | 是 | 提交后 textarea 变只读；「开始评分」是独立按钮 |
| **C3** 评分后独立记录证据 | 是 | `scored` 状态下仍有「记录学习证据」按钮，徽章为「待记录」 |
| **C4** 长期建议只在记录后出现 | 是（映射说明） | 原型未虚构建议卡；`implementation-map.md` 第 4 节说明读取条件 |
| 复习到期核查 | 是 | `review` 与 `review-not-due` 两个场景 |
| 复习身份以服务端题目为准 | 是 | 原型仅在「生成复习题」后才标记复习徽章 |

**四个区分在原型中可见**：

| 区分 | 原型表现 |
| --- | --- |
| 提交 ≠ 已评分 | 步骤 3 后步骤 2 变为 active，文案「提交不等于评分」 |
| 已评分 ≠ 已记录证据 | 步骤 2 完成后步骤 3 仍为 active，按钮独立 |
| 一次分数 ≠ 长期掌握 | 记录后文案「一次分数不代表长期掌握」 |
| 新题不带旧结果 | 点「再练一道」后进入 `conversation`，无任何评分残留 |

## 4. 三方案取舍

| 维度 | A · 单题专注 | B · 学习任务 | C · 双区辅导 |
| --- | --- | --- | --- |
| 阅读与作答效率 | **高** | 中 | 低 |
| 长文本适配 | **好** | 好（高度减少） | 差 |
| 反馈可读性 | **好** | 中 | 中 |
| 移动端体验 | **好** | 差 | 需额外 Sheet |
| 与现有代码兼容 | **最高** | 中 | 低 |
| 实施成本 | **最低** | 中高 | 最高 |

**推荐 A**，理由：练习的核心任务是「读题 → 作答 → 读懂反馈」，三者在时间上串行、空间上应同列；且现有 `mla-practice` 已是单列 860px，A 是整理而非推翻，B/C 都需要扩大改动面而收益无法证明。

## 5. 原型可操作性

### 5.1 覆盖的 13 个场景（P1-R1 更新）

全部截图见 `P1-assets/state-*.png`，均 `overflow = 0`、控制台 0 错误：

| 场景 | 关键内容 |
| --- | --- |
| `no-session` | 引导去 AI 学习，无出题入口 |
| `no-record` | 显式「初始化学习记录」 |
| `can-generate` | 概念 / 题型 / 目标 / 允许回退 |
| `generating` | 按钮 spinner + 表单禁用 |
| `generate-failed` | 服务端风格错误文案 |
| `awaiting` | 题目 + 输入 + 提交（步骤 1 active） |
| `submitted` | 只读答案 + 「开始评分」（步骤 2 active） |
| `evaluate-failed` | 原答案保留 + 「重新评分」+ 失败原因 |
| `scored` | 分数 75 + 三层反馈 + 独立记录按钮（步骤 3 active） |
| `recorded` | 三步全 done + 查看档案 + 再练一道 |
| `review-prep` | 到期日、证据数、会话状态、生成复习题（**尚未出题**） |
| `review-question` | 已生成的复习题：复习徽章 + 来源 + 题型 + 作答区（P1-R1 从旧的 `review` 拆出） |
| `review-not-due` | 红色提示「当前不需要复习」，不生成 |

### 5.2 三步交互实测（`three-step-flow`）

| 步骤 | 进度条状态 |
| --- | --- |
| 初始 | `active / pending / pending` |
| 输入后 | 相同（提交按钮由禁用变可用） |
| 提交后 | `done / active / pending` |
| 评分后 | `done / done / active` |
| 记录后 | `done / done / done` |
| 再练一道 | 回到无题目状态 |

断言结果：

| 检查 | 结果 |
| --- | --- |
| 无输入时提交按钮禁用 | 是（`disabledBefore: true`） |
| 输入后启用 | 是 |
| 提交后答案只读 | 是（`readonly` 存在） |
| **提交后、评分前无任何反馈** | 是（`.feedback` 数量为 0） |
| 评分后显示分数 | 是（`75`） |
| 评分后仍有独立记录按钮 | 是 |
| 记录后出现「再练一道」 | 是 |

### 5.3 原型控制

- 13 个场景下拉切换
- 普通练习 / 到期复习模式切换
- 深浅主题切换
- 顶部固定「原型演示 · 不连接真实数据」标识与说明条

## 6. 响应式与主题

| 视口 | 阅读列宽 | 横向溢出（浅/深） | 底部导航 | 主操作滚动后可见 |
| --- | ---: | ---: | --- | --- |
| 1440 × 900 | 860 | 0 / 0 | 无 | 是 |
| 1024 × 768 | 860 | 0 / 0 | 无 | 是 |
| 900 × 800 | 860 | 0 / 0 | 有 | 是 |
| 390 × 844 | 366 | 0 / 0 | 有 | 是（实测 `recordBottom 438 < navTop 792`） |
| 320 × 640 | 296 | 0 / 0 | 有 | 是（`336 < 588`） |

深色背景 `rgb(23,23,23)`，与产品 `--inno-background` 深色值一致。

**本轮修复的两个原型缺陷**（均在原型内，未触及产品代码）：

1. 手机底部导航原为半透明，滚动时会透出下方内容 → 改为不透明。
2. 锚点/键盘滚动会把作答框停在固定导航之后 → 为卡片、作答框与操作区加 `scroll-margin-bottom`；实测修复前 390px `textareaClear: false`，修复后 `true`。

3. **复习准备页去掉右栏**是 P2 的改动；原型已按单列呈现，正式代码仍是 `.mla-split`。

## 10. P1-R1 修订记录

> 本节保留 P1 的原始结论，并说明 P1-R1 修正了什么。原始测试数据未被覆盖。

### 10.1 修正的问题

| 问题 | 修复前 | 修复后 |
| --- | --- | --- |
| 场景切换空引用 | `PRESETS` 原地修改共享对象 `S`；`can-generate` 置 `question=null` 后，`awaiting` 执行 `S.question.review = false` 抛出 `Cannot set properties of null` | 改为 `createState()` 工厂，每次返回完整独立快照，嵌套对象不共享引用 |
| 场景状态残留 | `mode` / `attempt` / `review` 会跨场景残留 | 每个预设显式设置 `mode`，其余字段由工厂重建 |
| 模拟出题忽略题型 | 只读 `gen-concept`，生成后无题型徽章 | 读取知识点/题型/目标/回退；题型按选择映射，`自动选择` 固定为「自由回忆」 |
| 来源显示错误 | 来源与「允许模型知识回退」混为一谈 | 来源由演示数据决定（资料库已知主题 → 资料库，其余 → 模型知识），回退开关只表示许可 |
| 复习场景不完整 | 只有 `review`（已是出题状态）与 `review-not-due` | 拆为 `review-prep` / `review-question` / `review-not-due` |
| 异步回调污染 | `setTimeout` 无保护，切场景后旧回调仍会改写新场景 | 场景版本号 + 定时器取消，过期回调直接丢弃 |

### 10.2 原始结论

第 1–9 节的 P1 结论（方案选择、业务流程、响应式数据）在 P1-R1 中仍然成立，只有场景数量与 `review` 场景的说明被更新。完整的 P1-R1 验证见 `P1-R1-acceptance.md`。
