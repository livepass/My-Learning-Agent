## 1. 修复前的问题与复现

修复前的复现脚本（`P1-R1-assets/before-fix.png` + 控制台日志）记录了三处缺陷：

### 1.1 场景切换空引用

**复现**：场景选「可以出题」→ 再选「等待作答」。

**结果**：

```
pageerror: Cannot set properties of null (setting 'review')
```

**原因**：`PRESETS` 直接修改共享对象 `S`。「可以出题」把 `S.question = null`，随后「等待作答」执行 `S.question.review = false`，于是对 `null` 赋值。异常中断了渲染，页面停在空态（`hasPrompt: false`）。

### 1.2 模拟出题忽略题型与来源

**复现**：在「可以出题」里填知识点、题型选「迁移」、点生成。

**结果**：生成的题目只有 `来自模型知识` 一个徽章，**没有题型徽章**。原因是 `gen-go` 只读了 `gen-concept`，生成对象用 `...S.question` 展开，而那个对象可能已不存在或字段不全。

来源问题更隐蔽：当时来源固定写成 `model`，与「允许模型知识回退」这个**许可**开关混为一谈——回退开关说的是「允许用模型知识」，不是「这道题来自模型知识」。

### 1.3 复习场景不完整

**复现**：查看场景下拉。

**结果**：只有 `review` 与 `review-not-due`。`review` 直接就是「已出题」状态，**没有「复习准备」这个独立状态**——而准备页恰恰是到期核查、概念确认、会话选择的所在，是本轮复习流程最需要验收的一屏。

## 2. 代码修改说明

| 修改 | 位置 | 说明 |
| --- | --- | --- |
| 状态工厂 | `createState(scenario)` / `baseQuestion()` / `baseReview()` | 每次返回完整独立快照 |
| 场景加载 | `loadScenario(name)` | 递增版本号 → 取消定时器 → 重建状态 → 同步下拉 → 渲染 |
| 异步保护 | `afterDemoDelay()` / `cancelDemoTimers()` | 过期回调直接丢弃 |
| 生成逻辑 | `gen-go` 处理器 | 读取四个表单字段，构建完整题目对象 |
| 演示夹具 | `LIBRARY_CONCEPTS` / `conceptIdFor()` / `promptForKind()` | 来源与题型的确定性演示规则 |
| 复习场景 | `review-prep` / `review-question` / `review-not-due` | 三个独立预设 |
| 模式切换 | `#mode` 监听 | 走 `loadScenario`，不再原地改状态 |

## 3. 场景状态隔离方案

```js
function createState(scenario) {
  return {
    scenario, mode: "practice",
    hasSession: true, hasRecord: true,
    step: "awaiting_answer", status: "active",
    question: baseQuestion(),   // 每次新建
    attempt: null, draft: "",
    generating: false, generateError: null,
    submitting: false, evaluating: false, finalizing: false,
    review: baseReview(),       // 每次新建
    form: { kind: "", goal: "", fallback: true },
  };
}
```

要点：

- **没有共享引用**：`question`、`attempt`、`review` 都由工厂新建，预设只在返回值上做浅覆盖。
- **预设不再读旧状态**：每个预设的第一句就是 `createState(...)`，因此不可能依赖上一场景的对象。
- **`mode` 显式设置**：普通练习预设走 `createState` 的默认值 `practice`；三个复习预设都显式写 `mode: "review"`。
- **主题独立**：`theme` 是页面变量，不属于场景状态，切换场景时保留。
- **下拉同步**：`render()` 同时写回 `#scenario` 与 `#mode`，所以「练习/复习」切换后两个控件都与实际页面一致。

### 异步回调保护

```js
let sceneTicket = 0;
function afterDemoDelay(fn, ms) {
  const ticket = sceneTicket;
  const id = setTimeout(() => {
    timers.delete(id);
    if (ticket !== sceneTicket) return;   // 场景已切换 → 丢弃
    fn();
  }, ms);
  timers.add(id);
}
function loadScenario(name) {
  sceneTicket += 1;        // 让所有在途回调失效
  cancelDemoTimers();      // 并真正清掉定时器
  S = PRESETS[name]();
  ...
}
```

两道保险：版本号负责逻辑失效，`clearTimeout` 负责不留下悬挂的定时器。

## 4. 题目生成模拟规则

| 表单字段 | 用途 |
| --- | --- |
| 知识点 | 必填；决定 `conceptName`、`conceptId` 与题目文案 |
| 题型 | 决定 `kind`；「自动选择」固定解析为 `free_recall` |
| 关联目标 | 仅记录在 `S.form`，不参与模拟（后端推荐不在本轮范围） |
| 允许模型知识回退 | 仅表示许可，**不决定来源** |

**来源规则**（演示数据）：

- 知识点在 `LIBRARY_CONCEPTS`（装饰器的求值顺序 / 闭包与作用域 / 生成器与迭代器）中 → `来自资料库`
- 其余 → `来自模型知识`

**题目文案随题型变化**，避免徽章与内容不符：

| 题型 | 文案形态 |
| --- | --- |
| 自由回忆 | 「不看任何资料，先用自己的话解释…」 |
| 应用 | 「给出一段使用…的具体代码或步骤，说明它为什么能工作…」 |
| 迁移 | 「把…迁移到一个你熟悉的领域：说明它在那个场景里对应什么…」 |

生成后 **`attempt` 置空、`draft` 清空**，上一题的答案与评分不会带过来。

## 5. 三个复习场景

| 场景 | 标识 | 展示 | 明确不展示 |
| --- | --- | --- | --- |
| 到期复习准备 | `review-prep` | 知识点、到期日、证据数、会话准备状态、「生成复习题」 | 题目、作答框、评分 |
| 已生成复习题 | `review-question` | 复习徽章 + 来源 + 题型 + 题目 + 作答区 + 三步进度 | — |
| 复习不再到期 | `review-not-due` | 「当前不需要复习」提示、改为普通练习、返回今日学习 | **「生成复习题」按钮** |

**复习身份的语义说明**（写在准备页的提示条里）：复习题由服务端生成并保存来源，生成后页面才会把它标记为复习题。原型用 `review: true` 模拟这一结果，但页面上的模式开关**不会**改变题目身份——这一点与正式产品的 `question.review === true` 规则一致。
