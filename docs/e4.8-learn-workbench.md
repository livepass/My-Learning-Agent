# E4.8 — AI 学习工作台课程化

目标：把 AI 学习页从「中央聊天 + 右侧混合会话列表」改成「全局导航 + 课程与对话侧栏 + 中央聊天 + 可收起学习状态」，并保证**任何新建的 Web 学习对话都属于一门已存在的课程**。

本轮不改 Agent 运行时、不改 L1/L2/L3/B2 的权威数据结构，也不改动 E4.7 的归档、删除与学习证据规则。

## 1. 页面结构：改版前后

改版前：

```
[全局侧栏 184px] [聊天卡] [右侧 rail 224px：本次学习 + 全部日常会话]
```

改版后（桌面）：

```
[全局图标栏 64px] [课程/对话侧栏 260px] [聊天卡 自适应最宽] [学习状态 240px，可收起为 40px]
```

- 全局导航在学习页收窄为图标栏（`.mla-body--compact`），把宽度让给对话。
- 课程侧栏：`我的课程` + `创建课程`、每门课程可展开/收起、当前课程下的「新建对话」与历史对话、`未归类历史`、`归档课程 N 门` 与 `已归档会话 N` 入口。
- 每行对话显示标题、一行预览与 `自由学习` / `课程任务` 标记；选中行用 `aria-current` 高亮。
- 对话菜单提供重命名、归档、永久删除（复用既有 `sessionsStore` 方法与确认文案）。
- 「本次学习」检查点移入右侧可收起面板（`PanelRightClose/Open`）。
- 手机（≤900px）：课程侧栏变成抽屉（`打开课程列表` 按钮 + 遮罩），聊天保持整宽，学习状态在下方。

主要文件：`LearnPage.tsx`（重写）、`LearningWorkspace.tsx`、`AppShell.tsx`、`shell.css`、`learn-workbench-store.ts`（新增）。

## 2. 课程归属：前端与后端的双重约束

### 前端：先选课程才有输入框

状态来自 `learnWorkbenchStore`，**不复用** `coursesStore.selectedCourseId`（后者服务于课程详情页，切换时会清空计划、教材、记录等状态）。边界：

| 状态 | 表现 |
| --- | --- |
| 课程列表加载中 | 侧栏显示「正在加载课程…」，不显示输入框 |
| 课程读取失败 | 错误 + 重试，不伪装成「没有课程」 |
| 没有任何可用课程 | 创建引导（`CreateCourseDialog`）；全部归档时同时给「创建课程」「查看归档课程」 |
| 有课程但未选择 | 提示「先选择一门课程」，无输入框 |
| 已选择课程 | 空白工作台 + 输入框；首次发送才创建会话 |

选择课程不会创建任何会话：`?page=learn&course=<id>` 只表示"在这门课里"。

### 新建对话：延迟创建 + 幂等 request_id

`LearningWorkspace.send()` 在无会话时调用 `learnWorkbenchStore.ensureConversation()`：

1. 生成一次 `request_id`，调用 `POST /api/courses/:courseId/learning/start`（`task_id: null`）；
2. 服务端完成绑定与 B2 初始化后才返回；
3. 成功后 `openSession(...)`，随后才真正发送消息；
4. 失败保留草稿，**重试沿用同一个 `request_id`**（`_requestId` 只在成功或显式新建时清空），因此不会产生重复会话。

`LearningWorkspace` 不再直接走 `createSessionWith()` 创建学习对话；未提供 `createConversation` 时才回退到旧路径（兼容其他调用方）。

### 后端：会话必须属于课程

- `POST /api/chat`、`/api/chat/stream`：对**没有课程绑定、没有任何消息、且来源为 web** 的会话拒绝第一轮对话，返回 `409 course_required`。已经有消息的旧会话（历史）不受影响；非 web 会话（CLI / 企业微信 / 调度器）不受影响。这样即使绕过界面直接调接口，也无法新建"无课程的学习对话"。
- `learning/start`：归档 → `course_archived`；暂停 → `course_paused`；已完成 → `course_completed`（新增）。暂停/归档/完成课程都不能通过「新建对话」继续写入。
- `GET /api/sessions` 的 `course` 字段补充 `status` 与 `task_id`（`CourseStore.sessionCourseScopes`），侧栏据此区分「自由学习 / 课程任务」与课程状态，**不从标题、消息内容或下拉框推断**。
- 课程绑定的空会话也进入列表（`courseScopes.has(id)`），避免连续两次「新建对话」把前一个空白会话变成孤儿。

## 3. 任务会话与自由对话

- 自由对话：`task_id: null`，绑定来源 `free_question`；一个课程可以有任意多个。
- 任务会话：从今日学习/课程计划进入时仍走 `learning/start` 带 `task_id`，继续原来的会话（E4.4 规则不变；一个任务仍只有一个默认会话）。
- 侧栏按 `session.course.task_id` 标注两者，不增加模式选择步骤。

## 4. URL 与恢复

- `?page=learn`：课程选择入口，不自动打开任何会话。
- `?page=learn&course=<id>`：选定课程，空白工作台，不创建会话。
- `?page=learn&course=<id>&session=<id>`：以服务端绑定为准打开会话；若 URL 的 course 与绑定冲突，用 `replace` 把 course 纠正为真实绑定的课程。
- `navigation.ts` 不再在进入 learn 时删除 `course` 参数；`navigate("learn", { learn: { courseId, session } })` 显式控制清除/保留。
- 刷新、直达链接、前进/后退都按 URL 复原；侧栏切换课程时关闭前一个会话并清空输入草稿。

## 5. 课程状态与历史

- `in_progress`：可创建/继续对话。
- `paused`：输入区替换为「课程已暂停」+「继续课程」。
- `archived`：会话只读（沿用 E4.7 的服务端拒绝），无会话时提示去归档中心恢复。
- `completed`：只展示历史，不隐式开始新学习（服务端同样拒绝）。
- 未归类历史：保留入口，只读/可继续查看；不会自动分配到最近课程，也不会因为打开而被改绑。

覆盖的验收点：

1. 无课程时没有输入框，可从空状态创建第一门课程；
2. 有课程未选择时不能发送；
3. 创建课程后自动选中、空白工作台、不创建聊天文件；
4. 同一课程两个自由对话（服务端两个绑定，`task_id` 均为 null）；
5. A 课程的对话不出现在 B；
6. 任务进入仍复用任务会话（`learning-start` 既有用例 + 绑定规则未变）；
7. 切换课程清空草稿、关闭前一会话；
8. 刷新/深链接恢复课程与会话，冲突时以绑定为准；
9. 暂停/归档/完成课程不能新建对话（接口 409）；
10. 未归类会话可访问、不被改绑。
