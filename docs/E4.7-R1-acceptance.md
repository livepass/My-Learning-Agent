# E4.7-R1 验收记录：删除修复、归档中心与父子状态一致性

三个阶段按顺序实施，每个阶段独立提交。本文件记录复现、根因、修复与验收结果。

## R1a 删除故障与状态修复

### 复现（真实 HTTP + 前端）

环境：隔离数据目录启动构建产物，Chrome（headless）驱动真实页面，另用 `curl` 直接验证接口。

| # | 复现步骤 | 修复前现象 |
| --- | --- | --- |
| A | 空课程 + 一条 `learning_starts`（`status=creating`，无 `session_id`）→ `GET /api/courses/:id/delete-preview` | `deletable:false`，blocker `pending_learning_start`；`DELETE` 返回 409；前端确认框只有「归档课程」，提示「请稍后重试」但永远不会恢复 |
| B | 启用计划 → 归档 → 打开课程详情「学习计划」 | 计划行只有「查看记录」，没有「删除」；而后端 `delete-preview` 返回 `deletable:true`，`DELETE` 返回 200 |
| C | 归档课程后 `POST /learning/start`、`PATCH /tasks/:id`、`POST /sessions` | 分别返回 201/200/201：归档课程仍能创建会话、推进任务、初始化 B2 记录，并绑定自由会话 |

### 根因

- **A：学习启动预留泄漏。** `courses/learning-start.ts` 在创建会话前写 `creating` 预留；当 `createSession()` 返回 `null`（对话队列被占用）时直接返回 409，没有 `abortLearningStart`。记录永久停留，而删除检查把它视为「未结束的启动请求」。任何一次在队列忙时点击「开始学习」，都会让该课程永久不可删除。
- **B：前端状态分支不完整。** `CoursePlanPanel` 只覆盖 `draft` / `active`，`archived` 分支仅渲染「查看记录」，E4.7 的后端能力没有入口。
- **C：归档只改变了展示。** `CourseStore` 的写事务与 `startLearning` 只校验课程存在，不校验 `status`；任务进度校验只看计划状态。归档因此没有冻结学习推进。

### 修复

1. `learning-start.ts`：`createSession()` 失败时同步撤销预留；`startLearning` 在课程已归档时直接返回 409 `course_archived`，不创建会话。
2. `course-store.ts`：新增 `COURSE_ARCHIVED` 与 `assertCourseNotArchived`，在写事务内拦截 `reserveLearningStart`、`bindSession`、`confirmPlan`、`applyPlanAdjustment`、`updateTask`；规划编辑与记录清理仍允许（不产生证据）。
3. `course-store.ts`：无 `session_id` 且超过 15 分钟的 `creating/created` 记录视为已放弃的尝试，不再阻塞删除（删除时一并清理）；已命名会话的记录无论多久仍然阻塞。
4. `sessions.ts`：出题、作答、评分、定稿四个会写 B2/L1 的接口，在会话所属课程归档时返回 409 `course_archived`。
5. `CoursePlanPanel`：归档且无学习记录的计划补上「删除」；归档课程显示只读提示并禁用「确认启用」。
6. `course-context.ts`：上下文携带 `courseArchived`，供会话路由判断。

### 验收

- 修复后同一复现：过期泄漏记录 → `deletable:true`，`DELETE` 200 并清理 `learning_starts:1`；草稿课程确认框出现「继续删除」并删除成功（课程 404）；归档计划行出现「删除」并删除成功（计划 404）。
- 归档课程：`learning/start`、`PATCH task`、`POST /sessions` 均 409 `course_archived`，任务保持 `pending`，未创建任何会话文件。
- 测试：新增 `learning-start.test.ts` 2 例、`course-store.lifecycle.test.ts` 3 例、`courses.lifecycle.test.ts` 1 例、`CourseDetailPage.test.tsx` 2 例；课程与会话相关 16 个文件 / 194 例、学习与路由 23 个文件 / 436 例全部通过。
