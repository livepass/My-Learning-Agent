# E4.7-R1 验收记录：删除修复、归档中心与父子状态一致性

三个阶段按顺序实施，每个阶段独立提交。本文件记录复现、根因、修复与验收结果。

## R1a 删除故障与状态修复

### 复现（真实 HTTP + 前端）

环境：隔离数据目录启动构建产物，Chrome（headless）驱动真实页面，另用 `curl` 直接验证接口。

| # | 复现步骤 | 修复前现象 |
| --- | --- | --- |
| A | 空课程 + 一条 `learning_starts`（`status=creating`，无 `session_id`）→ `GET /api/courses/:id/delete-preview` | `deletable:false`，blocker `pending_learning_start`；`DELETE` 返回 409；前端确认框只有「归档课程」，提示「请稍后重试」但永远不会恢复 |
| B | 启用计划 → 归档 → 打开课程详情「学习计划」 | 计划行只有「查看记录」，没有「删除」；而后端 `delete-preview` 返回 `deletable:true`，`DELETE` 返回 200 |
| C | 归档课程后 `POST /learning/start`、`PATCH /tasks/:id`、`POST /sessions` | 分别返回 201/200/201：归档课程仍能创建会话、推进任务、初始化 B2 记录，并绑定自由会话 |

### 根因

- **A：学习启动预留泄漏。** `courses/learning-start.ts` 在创建会话前写 `creating` 预留；当 `createSession()` 返回 `null`（对话队列被占用）时直接返回 409，没有 `abortLearningStart`。记录永久停留，而删除检查把它视为「未结束的启动请求」。任何一次在队列忙时点击「开始学习」，都会让该课程永久不可删除。
- **B：前端状态分支不完整。** `CoursePlanPanel` 只覆盖 `draft` / `active`，`archived` 分支仅渲染「查看记录」，E4.7 的后端能力没有入口。
- **C：归档只改变了展示。** `CourseStore` 的写事务与 `startLearning` 只校验课程存在，不校验 `status`；任务进度校验只看计划状态。归档因此没有冻结学习推进。

### 修复

1. `learning-start.ts`：`createSession()` 失败时同步撤销预留；`startLearning` 在课程已归档时直接返回 409 `course_archived`，不创建会话。
2. `course-store.ts`：新增 `COURSE_ARCHIVED` 与 `assertCourseNotArchived`，在写事务内拦截 `reserveLearningStart`、`bindSession`、`confirmPlan`、`applyPlanAdjustment`、`updateTask`；规划编辑与记录清理仍允许（不产生证据）。
3. `course-store.ts`：无 `session_id` 且超过 15 分钟的 `creating/created` 记录视为已放弃的尝试，不再阻塞删除（删除时一并清理）；已命名会话的记录无论多久仍然阻塞。
4. `sessions.ts`：出题、作答、评分、定稿四个会写 B2/L1 的接口，在会话所属课程归档时返回 409 `course_archived`。
5. `CoursePlanPanel`：归档且无学习记录的计划补上「删除」；归档课程显示只读提示并禁用「确认启用」。
6. `course-context.ts`：上下文携带 `courseArchived`，供会话路由判断。

### 验收

- 修复后同一复现：过期泄漏记录 → `deletable:true`，`DELETE` 200 并清理 `learning_starts:1`；草稿课程确认框出现「继续删除」并删除成功（课程 404）；归档计划行出现「删除」并删除成功（计划 404）。
- 归档课程：`learning/start`、`PATCH task`、`POST /sessions` 均 409 `course_archived`，任务保持 `pending`，未创建任何会话文件。
- 测试：新增 `learning-start.test.ts` 2 例、`course-store.lifecycle.test.ts` 3 例、`courses.lifecycle.test.ts` 1 例、`CourseDetailPage.test.tsx` 2 例；课程与会话相关 16 个文件 / 194 例、学习与路由 23 个文件 / 436 例全部通过。

## R1c 父课程与子会话归档状态

### 状态模型

两个独立状态，互不写入：

- 课程归档状态：`Course.status === "archived"`；
- 会话手动归档状态：`sessions/archives.json[id]`。

日常可见性由服务端派生：`daily_visible = !session.archived && course?.status !== "archived"`。课程归档/恢复**不会**批量改写 `archives.json`；`GET /api/sessions` 同时返回 `archived`（自身）、`course`（父课程含 `archived`）与 `daily_visible`（派生），归档中心据此解释原因并区分「手动归档 / 随课程归档」。

## R1 最终收尾补丁（四项）

基于 `51f3839`，只修复以下四项，未改动其他功能或架构。

### 1. 恢复课程后的继续学习入口

**问题**：恢复归档课程后状态固定为 `paused`，但前端只有被禁用的「开始学习」，没有任何入口把状态改回 `in_progress`；同时后端 `learning/start` 只拦 `archived`，`paused` 课程仍可被直接调用创建会话——前后端权限不一致。

**修复**：

- 新增 `POST /api/courses/:courseId/resume`（`CourseStore.resumeCourse`）：仅允许 `paused → in_progress`，`in_progress` 幂等；`archived` 返回 409 `course_archived` 并指向 restore；`completed` 拒绝。**不创建会话、绑定或学习记录**。
- 今日学习课程卡片在 `paused` 时用「继续课程」替换「开始学习」；课程详情页头部同样提供「继续课程」。
- 后端 `learning/start` 对 `paused` 返回 409 `course_paused`，与前端禁用保持一致；`resume` 后才恢复。
- `PATCH /api/courses/:courseId` 不能把 `archived` 改为任何其他状态（409 `course_archived`），只能走 `POST /restore`，防止通用状态接口绕过正式恢复流程。

### 2. 今日学习的最近会话过滤

**问题**：`TodayPage` 的「最近学习」只判断 `!session.archived`，父课程归档、会话自身未归档的会话仍会出现在首页；数量统计也按全部会话计算。

**修复**：抽出 `isDailyVisible`（`daily_visible ?? archived !== true`），学习页与今日页共用；最近学习与「N 个会话」使用同一过滤结果。

### 3. 归档课程中心补充删除

**问题**：归档课程只能恢复，没有删除入口。

**修复**：`ArchivedCoursesSettings` 每行新增「删除课程」，复用 `DeletionDialog` 与 `delete-preview`：

- 无真实学习记录：展示将删除的计划/阶段/任务数，二次确认后删除，成功后刷新归档列表；
- 有学习会话、已开始任务、B2 证据或 L1 掌握状态：逐条列出 blocker，不提供「继续删除」；
- L1/L2/L3/B2 保护仍由 E4.7 的删除事务与证据探测执行，未新增旁路。

### 4. 手动归档会话的只读一致性

**问题**：手动归档的会话从日常列表移除，但直接打开历史仍显示输入框；服务端聊天与学习写入也没有拦截，只读只是「列表里看不到」。

**修复**：

- 前端：`LearningWorkspace` 的 `readOnly` 区分 `session` / `course`，分别提示去「归档会话」或「归档课程」恢复；学习检查点区域隐藏初始化、暂停、恢复；「查看历史」只读，不调用恢复接口。
- 服务端：新增共享模块 `server/session-archive-store.ts`（`archives.json` 的唯一读取入口）；`/api/chat`、`/api/chat/stream`、`/api/chat/question-response` 与学习记录的 init/pause/resume/generate/answer/evaluate/finalize 统一拒绝手动归档会话（409 `session_archived`），课程归档仍为 `course_archived`。
- 打开历史不会改写 `archives.json`；恢复会话仍需显式操作。

## Go/No-Go 结论

**Go（仅限 E4.7-R1 收尾）**。

四项缺陷均已复现、修复并有回归测试与真实浏览器验收：

1. 恢复后的 `paused` 课程有明确的「继续课程」；该操作只改状态，不建会话/记录；后端不再允许绕过恢复流程，也不允许 `paused` 直接开始学习。
2. 今日学习「最近学习」按服务端 `daily_visible` 过滤，计数同源；父课程归档的会话不再泄漏到首页。
3. 归档课程中心可删除无历史课程（二次确认、列表刷新），有历史时逐条说明原因且无法继续删除，L1/L2/L3/B2 保护未变。
4. 手动归档会话在打开历史时只读；聊天与全部学习写接口在服务端拒绝，B2 字节不变、模型调用为 0；查看历史不会自动恢复。

不进入 E5 的前置条件仅剩产品决策（是否开始真实学习试运行）；本次补丁未新增回收站、权限或其他功能。
