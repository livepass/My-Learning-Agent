## 1. 改动内容

### 1.1 厂商预设拆分（`provider-presets.ts`）

- `BRAND_PRESETS`：六个品牌厂商的数组字面量（即卡片网格的数据源）。
- `CUSTOM_PRESET`：独立常量（`id: "custom"`），不再是第七张卡片；描述与品牌色保留，供表单头部图标与文案使用。
- `PROVIDER_PRESETS = [...BRAND_PRESETS, CUSTOM_PRESET]`：兼容性视图，仅用于品牌查找。
- `findPreset()` 只在 `BRAND_PRESETS` 中匹配（含 `includes` 子串匹配），注释说明「custom 永不匹配」：自定义厂商没有品牌，用户命名的 provider 不能被打上预设的标签。

### 1.2 入口按钮（`AddProviderWizard.tsx`）

- 厂商标题行从 `ModelsSettings.tsx` 移入向导组件（向导拥有网格与表单状态，标题随之归属同一所有者），右侧放「+ 新增模型厂商」`Button variant="secondary"`：
  - 点击 → `selectPreset(CUSTOM_PRESET)`，完全复用既有自定义表单（提供方 ID + Base URL 在表单顶部，其余字段与六厂商一致；高级选项里自定义厂商隐藏重复的 ID/URL 字段）。
  - 表单头部图标改用新增的 `PresetIcon({ preset })`：custom 走 `findPreset` 时被排除，直接按 id 查会退化成首字母「C」，因此按 preset 元数据渲染，正确显示「+」灰色图标块。`ProviderIcon(providerId)` 变为 `PresetIcon` 的按 id 包装，行为不变。
- `ModelsSettings.tsx` 因此只渲染 `<AddProviderWizard providers={...} />`，API 面板不再有平行的标题块。

### 1.3 文案

- 新增 `settings.models.addProvider`：zh「新增模型厂商」/ en「Add model vendor」。其余文案全部复用。

## 3. 端到端实测（真实后端）

1. 点击「+ 新增模型厂商」→ 表单出现，图标为「+」灰块、标题「自定义」。
2. 填入 提供方 ID `e31-ui-check`、Base URL、API Key、模型 ID `test-model` → 保存成功。
3. `/api/settings` 出现 `e31-ui-check`（模型 `test-model`，key 已掩码存储）。
4. 刷新后当前模型下拉出现 `test-model · API`，选择后卡片更新且持久化到 config。
5. 清理：默认模型恢复 `magpie/workbuddy/hy3`，测试 provider 已删除，`runtime/config/config.json` 复原（仅 `ui.theme` 因本轮调试固定为 `light`，与页面当前显示一致）。
