# E4.7 课程与学习计划删除、归档管理

本文件是 E4.7 的验收记录：接口契约、删除/归档规则、测试与浏览器验收结果。

## 1. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/courses/:courseId/delete-preview` | 删除前置检查：将删除的阶段/任务/计划数量、是否关联教材、不可删除原因 |
| `DELETE` | `/api/courses/:courseId` | 永久删除没有学习历史的课程 |
| `GET` | `/api/courses/:courseId/plans/:planId/delete-preview` | 计划的删除前置检查 |
| `DELETE` | `/api/courses/:courseId/plans/:planId` | 永久删除草稿或已启用但未开始的计划 |
| `POST` | `/api/courses/:courseId/plans/:planId/archive` | 归档计划（保留任务、会话与记录，幂等） |
| `POST` | `/api/courses/:courseId/archive` | 归档课程（已有接口，行为不变） |

删除被拒绝时返回 `409`，`blockers` 逐条给出原因，而不是一条笼统错误：

```json
{
  "error": "course_conflict",
  "message": "该课程已有真实学习记录，不能永久删除；请改用归档。",
  "category": "courses",
  "blockers": [
    { "code": "course_sessions", "count": 1, "message": "该课程已有 1 个学习会话，会话与学习记录必须保留，请改用归档。" },
    { "code": "learning_evidence", "count": 1, "message": "该课程已有 1 个会话产生正式学习证据（B2），只能归档。" }
  ]
}
```

阻塞码：`course_sessions`、`plan_sessions`、`started_tasks`、`pending_learning_start`、`learning_evidence`（B2）、`mastery_states`（L1）、`plan_completed`。

## 2. 删除规则（全部在 `CourseStore` 写事务内）

课程删除前检查：

1. 该课程的学习会话绑定；
2. 已开始（`in_progress`）或已完成的任务；
3. 尚未结束（`creating` / `created`）的学习启动请求；
4. 归属于该课程的正式学习证据（B2 已 `evidence_recorded` 及之后阶段）与 L1 掌握状态（`knowledge_state.course_id`）。

可删除时，一次 `state.json` 原子写入清理：课程、计划、阶段、未开始任务、目标关联、教材关联、每日学习时间、该课程的启动请求记录。
**不删除**：L2 原始教材（只解除关联）、共享学习目标、其他课程的会话与记录、L1/L3/B2。

计划删除前检查：计划任务是否已开始/完成、是否绑定会话、是否有未结束的启动请求、计划是否已完成。可删除时同一事务删除计划、阶段、未开始任务与相关启动记录；删除当前启用计划后不会自动启用其他草稿，课程回到 `no_active_plan`。

并发保护：证据探测（B2/L1）在 `CourseStore` 的串行写事务内执行，覆盖「检查—删除」窗口。并发的 `learning/start` 要么在删除前已写入启动记录（删除被拒），要么在课程消失后失败，不会留下悬挂会话绑定。

## 3. 前端

- 今日学习课程卡片：「更多操作」菜单（查看课程 / 归档课程 / 删除课程）；
- 课程详情页头部：「课程管理」菜单（归档课程 / 删除课程）；
- 学习计划列表：草稿「编辑 / 确认启用 / 删除」，未开始的启用计划「归档 / 删除」，已有记录的计划「归档 / 查看记录」；
- 删除确认对话框：名称、阶段数与任务数、是否关联教材、不可删除原因，二次确认后执行；点击菜单项只读取 `delete-preview`，不删除任何数据；被拒绝时只提供归档。
